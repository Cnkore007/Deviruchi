# Deviruchi 交互式配置向导与参考文档系统

## 概述

为 Deviruchi 游戏服务器添加两个核心功能：
1. **首次启动交互式向导** — 引导用户快速配置服务器参数
2. **自动参考文档生成** — 每次启动时更新物品/怪物/技能/地图列表

## 设计目标

- 新用户首次启动时自动引导配置，无需手动编辑 TOML
- 所有配置集中在 `config/server.toml`，用户后续可直接编辑
- 参考文档自动同步数据库，方便用户查找 ID 等信息

## 一、交互式向导

### 触发条件

服务器启动时检测 `config/server.toml` 不存在 → 自动进入向导模式。

### 配置问题序列

| 序号 | 问题 | 默认值 | 输入类型 |
|------|------|--------|----------|
| 1 | 服务器名称 | Deviruchi | 字符串 |
| 2 | 基础经验倍率 (Base EXP Rate) | 1.0 | 浮点数（1.0 = 100%） |
| 3 | 职业经验倍率 (Job EXP Rate) | 1.0 | 浮点数 |
| 4 | 物品掉落倍率 (Item Drop Rate) | 1.0 | 浮点数 |
| 5 | Zeny 掉落倍率 | 1.0 | 浮点数 |
| 6 | 最大基础等级 | 99 | 整数 |
| 7 | 最大职业等级 | 50 | 整数 |
| 8 | 死亡经验惩罚 | 关闭 | 开/关 |
| 9 | 默认出生地图 | prontera | 字符串 |
| 10 | 最大玩家数 | 5000 | 整数 |

### 交互流程

```
============================================
  Deviruchi 服务器配置向导
============================================
检测到首次运行，将引导您完成基础配置。
所有选项可直接回车使用默认值。

物品掉落倍率 (1.0 = 100%) [1.0]: 2.0

```

### 输出文件

生成 `config/server.toml`，格式与现有结构完全一致。

## 三、实现方案

### 修改文件清单

| 文件 | 修改内容 |
|------|----------|
| `src/cli.rs` | 添加 `setup` 子命令（显式触发向导） |
| `src/main.rs` | 启动时检测配置文件是否存在，不存在则触发向导 |
| `src/core/config.rs` | 添加向导交互逻辑 + 文档生成逻辑 |
| `src/core/guide.rs` | 新文件：参考文档生成器 |

### 核心逻辑

```
main() {
    if config not exists {
        run_setup_wizard()  // 交互式向导
    }

    config = load_config()

    if db files changed since last guide update {
        generate_guide()    // 生成参考文档
    }

    start_server()
}
```

### 向导实现

使用 `std::io` 读取用户输入，逐行提示并解析。
- 空输入 → 使用默认值
- 数值输入 → 验证范围
- 生成 TOML 格式写入文件

### 文档生成实现

1. 使用 `serde_yaml` 解析 `db/*.yml`
2. 按类型分类物品
3. 格式化为 Markdown 表格
4. 写入 `config/guide.md`

## 四、测试计划

| 测试项 | 验证方式 |
|--------|----------|
| 向导首次触发 | 删除 config/server.toml，启动服务器 |
| 默认值正确性 | 全部回车，检查生成的 TOML |
| 自定义值 | 输入自定义倍率，检查生成的 TOML |
| 文档生成 | 启动后检查 config/guide.md 内容 |
| 文档增量更新 | 修改 db 文件后重启，检查文档更新 |
| 手动编辑兼容 | 手动修改 server.toml 后启动，验证正常加载 |
